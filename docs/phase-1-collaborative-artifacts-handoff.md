## 1. 阶段目标与非目标

### 1.1 目标

让用户从一次或多次文献对话中整理出独立的调研文档：能够直接修改、调整顺序、保留引用、局部追问，并在自己确认后采纳 agent 的修改建议。原对话和 Context Tree 继续保留，可回溯和分支探索。

最小闭环：

> 已有论文对话 → 加入调研文档 → 用户修改 → 查看来源 → 局部追问 → 预览并采纳修改建议 → 刷新后状态完整保留。

用户看到的成果不再只是“加宽的聊天记录”。文档可以重排和编辑；聊天历史记录形成过程，二者通过稳定引用关联，不相互覆盖。

### 1.2 必须交付

1. 独立文档及稳定 ID 的内容块，可持久化、编辑、排序、移出文档和撤销最近修改。
2. 从回答或选中段落明确加入文档，保留来源；不自动把每个回答变成正文。
3. 来源会话与论文证据分开表示；已有页码、图表引用可回到正确 PDF。
4. 针对文档块/选区追问，新的回答仍进入会话树，可从文档找到该追问。
5. agent 对正文的修改先形成提案，只有用户接受后才能应用；支持版本冲突保护。
6. 可选 Context Tree 保留现有浏览、切换、分支、追问、论文绑定等行为。
7. 保存状态、错误、草稿恢复与兼容迁移明确可见，有行为测试。

### 1.3 明确不做

- 不实现模型生成的知识思维导图、概念关系图、自由画板或完整演示编辑器。
- 不将 Context Tree 重命名或重解释为知识图谱；不把它变成不可分支的装饰。
- 不与 LivingCanvas 合仓，不搬迁整套前端，不新建第二个 Agent 后端。
- 不实现全自动搜索到报告的持久任务调度、完整暂停恢复系统或多 Agent 编排。
- 不引入向量数据库、通用知识图谱、CRDT、多人实时协作或通用 UI DSL。
- 不大改 PDF/OCR/图表识别算法；本阶段只接入已经存在且可定位的材料。
- 不要求滚动语义摘要；先确保有界、正确、可解释的上下文装配。
- 不声称实现了理论创新、提高理解效果或节约 token；这些留待评测。

## 2. 设计决策：保留什么，修订什么

| 原有设计 | 本阶段决策 |
|---|---|
| 主线是唯一事实源 | Workspace 保存各类权威状态：会话树、文档、证据引用和修改提案各负其责；文档不是原始论文的事实替代品 |
| 一个阶段块对应一个模型回合 | 分离：一个回合可产生多个成果块；一个成果块可经历多次会话与人工编辑 |
| 所有地图都是只读投影 | 区分 Context Tree、文档大纲、未来知识画布；各自保有不同语义 |
| 支线永不与主线平级 | 局部追问默认附着与折叠，但用户可以把其中的内容加入任意文档位置 |
| 每步固定 search→download→summary→review→figures | 作为可用工作流建议保留，不作为文档结构或状态机的强制限制 |
| 新节点继承完整工作记忆 | 历史保存与模型请求分离；按当前任务选择材料，不盲目拼接全部历史 |

Context Tree 是用户选择保留的过程回溯与分支管理工具。本阶段不争论它是否最优，也不以文档优先为理由删减它。它记录可观察的会话/工具过程，不宣称展示模型完整内部推理。

三种结构的明确边界：

- **Context Tree**：提问依赖、回答、局部追问与分支；继续影响会话路径上下文。
- **文档大纲**：根据用户当前标题和块顺序生成的确定性导航；不是模型理解产物。
- **未来知识画布**：概念、证据、方法及关系的共享编辑空间，本阶段仅留稳定引用边界。

默认不让树图占据主工作面，保留显式入口和用户偏好。切换显示不改变实际树结构或偷偷改变上下文模式。

## 4. 用户交互规格

### 4.1 工作区与焦点

保留对话，新增“调研文档”工作面；Context Tree 是可选的导航/分支面板。可用页签或主面板切换，不要求固定三栏。沿用当前极简样式、主题配置、Markdown 与 LaTeX 渲染。

分别保存并维护：当前会话节点、当前文档、当前文档块。不得复用一个 `selectedId` 表示所有焦点。点击文档块不得悄悄切换会话分支；跳回源对话则是显式动作。

有文档时可恢复上次打开的文档；没有文档时仍允许正常聊天。不得用空白文档挡住现有应用。

### 4.2 创建与加入内容

- 提供“新建调研文档”，允许修改标题；模型不必参与标题生成。
- 对已完成的回答提供“加入文档”，并支持从回答选区加入；不复制隐藏推理、工具进度或下一步按钮。
- 选区只取可见文本或安全重建的 Markdown，禁止把任意选区 HTML 直接入库。
- 新块获得独立 ID 和源节点/源内容版本标识；引用与图表只带入该内容实际关联的材料。
- 同一个完成响应的重复点击、网络重试不能创建重复块；用户显式“再复制一份”才创建新对象。
- 默认追加末尾；块级向上/向下按钮足以完成排序，不强制拖拽编辑器。
- 图表以稳定资源引用插入，保存图注和来源，不把图片 base64 放入 Workspace JSON。
- 流式未完成内容不能自动作为正式成果保存；失败/取消答案只有用户明确选择时才可保存，并标记不完整。

### 4.3 编辑与保存

- 第一版可采用 Markdown 文本编辑＋预览，不要求所见即所得编辑器。
- 支持块标题、正文、排序与移出；“移出文档”不能删除来源会话、论文文件或图表资源。
- 明确显示“未保存 / 保存中 / 已保存 / 保存失败 / 版本冲突”。
- 编辑器输入草稿先进入受限的本地恢复机制；服务端确认成功后才显示“已保存”。
- 不承诺浏览器异常终止绝不丢字；正常刷新和切换必须能恢复已缓存草稿，不能只依赖 `beforeunload` 网络请求。
- 保存失败后保留编辑内容，提供重试；本地缓存满时显示错误并允许复制/导出草稿，不清空内容。
- 支持撤销最近一次已提交的正文修改、排序、移出或提案采纳。第一版仅要求本次页面会话内的撤销，刷新后不承诺撤销栈保留；界面/README 说明边界。
- 撤销是新的有版本写入，不回退全局 revision；存在外部修改时先报冲突，不能把整份旧快照直接覆盖回去。

### 4.4 来源与证据

每块至少能区分“来自哪次回答”和“引用了哪份论文材料”。源回答本身不是论文证据。

- 来源节点存在时可跳回；被删除或重新生成后，仍保留加入时的内容快照/版本标识，显示来源不可用或已变化。
- 有效论文引用能打开对应 paperId 和页码，不使用当前树分支 PDF 代替。
- 一个块可引用多篇论文；不要沿用单一 `paperId` 强行覆盖其他引用。
- 只有论文 ID、没有页码时，允许打开论文，但标注“未定位页码”；不得猜页码。
- 有页码只说明定位存在，不等于结论已被验证；不自动显示“事实已核验”。
- 用户改写正文后，已有来源默认仍保留，但证据与新表述的对应状态标为“待复核”；用户可以移除或重新确认对应关系。
- 图表应尽量沿用现有稳定 visual/artifact 引用；若现有 URL 不稳定，应补最小解析映射，不更改图表识别算法。
- 来源文件失效时保留文档和引用元数据，显示明确缺失提示，不静默替换另一篇 PDF。

### 4.5 文档局部追问

选中文档片段时，输入区显示引用片段和所属文档块，提供取消引用。一次选区必须属于一个块；跨块选择先提示缩小范围，避免隐式拼接。

提交时固定一份 anchor：文档 ID、块 ID、块内容版本、原始选中文字、可选前后文。该 anchor 与提问一起持久化。

新的对话仍是树节点，附带 document anchor；不把回答自动写进原块。挂载规则：优先使用该块仍存在的源节点；没有唯一可用源节点时使用当前选中节点，并在发送前显示挂载目标，允许用户改选。文档引用的论文与挂载节点不一致时，显式文档请求的材料优先，不能静默使用该分支的另一篇论文。

文档显示“相关追问 N”及跳转。追问结果可由用户加入文档，或显式发起修改建议。原文后来变动时，保留追问当时的引用快照并标记历史版本，不强行把 anchor 定位到错误文字。

### 4.6 agent 修改建议

使用显式动作“请 agent 修改此块”，而不是让普通回答自动改文档。第一版只允许针对一个块提出标题/正文的完整替换建议，不支持 agent 删除文档、重排全文或跨文档批量写入。

提案流程：

1. 服务端捕获目标块当前版本与 hash，构造修改请求。
2. agent 返回受校验的提案，运行时保存为 pending，不改变正文。
3. UI 展示原文与建议，至少有并排/前后预览；新增和删除内容应容易辨认。
4. 用户接受或拒绝。接受时再次验证目标块版本及 hash，匹配才原子更新。
5. 用户已修改目标块时将提案标为 conflicted，允许查看、复制或重新生成，不允许直接覆盖。

建议通过专用结构化工具 `propose_document_patch` 实现。工具参数只需要新标题/正文、变更说明及允许引用的证据 ID；目标对象和基线由服务端请求范围绑定，不能由模型随意指定。没有文档修改作用域时不要暴露该工具。

可以采用现有模型适配器支持的等价结构化实现，但不能依赖从普通回答中用宽松正则“猜出 JSON”后直接写正文。模型不支持或输出校验失败时，显示错误并保留普通回答，文档不变；不以自然语言“已修改”冒充成功。

拒绝提案不删除会话；接受/拒绝重复请求幂等。生成中的取消和迟到响应不能直接修改正文；被取消请求不得随后产生自动弹出的有效提案。

## 5. 最小数据契约

以下为建议逻辑结构，不要求字段拼写完全一致。为避免过度建设，当前 JSON 持久化可以继续使用，明确只支持现有单进程本地部署；多进程写入需要额外锁/数据库，不能把线程锁宣传为跨进程安全。

```text
WorkspaceEnvelope
  schema_version: 2
  revision: 单调递增
  state
    tree: 原结构兼容保留
    active_paper: 兼容旧数据，不成为文档的全局论文指针
    documents: {documentId -> ResearchDocument}
    evidence: {evidenceId -> EvidenceRef}
    proposals: {proposalId -> DocumentPatchProposal}
    view: 当前文档/块与工作面偏好（可与本地 UI 偏好分离）

ResearchDocument
  id, title, revision, createdAt, updatedAt
  blockOrder: 有序 blockId 列表
  blocks: {blockId -> DocumentBlock}

DocumentBlock
  id, type: markdown | figure
  title, markdown（figure 的文字为图注/解释）
  assetRef?（figure 必需，引用现有资源，不接受任意本地路径）
  revision, contentHash, createdAt, updatedAt
  createdBy, updatedBy: human | agent
  sourceRefs[]: nodeId + 内容版本/hash + 必要快照
  evidenceIds[]
  evidenceReviewState: unreviewed | needs_review | user_checked

EvidenceRef
  id, paperId, sourceType: paper | figure | table
  page?（内部统一一基页码），pageLabel?（仅展示）
  quote?, visualId?, assetRef?, bbox?（有可靠坐标才存）
  locatorStatus: located | paper_only | missing

DocumentAnchor（保存在局部追问的树节点上）
  documentId, blockId, blockRevision, blockContentHash
  quote, prefix?, suffix?

DocumentPatchProposal
  id, documentId, blockId, baseBlockRevision, baseContentHash
  replacementTitle?, replacementMarkdown, evidenceIds[]
  explanation, sourceNodeId?, requestId, createdAt
  status: pending | accepted | rejected | conflicted
```

补充不变量：

- ID 由应用生成，实体身份不依赖标题、数组位置或像素坐标。
- `blockOrder` 与块集合一致，无重复、无悬空块；输入有明确长度/数量上限。
- 同一块的正文和引用只有一份权威状态；聊天快照不随正文编辑而改写。
- `createdBy/updatedBy` 表示内容作者，不表示审批人。接受 agent 提案后作者仍记 agent，可另记 acceptedBy=human。
- hash 由运行时按固定规则计算，不信任模型传来的 hash；版本检查优先采用服务端读取值。
- 本阶段删除文档/块不触发物理论文或图表清理，也不自动清理证据。资源回收另立任务。
- 文档 schema version 与 LivingCanvas 的 World schema version 相互独立。
- 未来画布通过 `{workspaceId, documentId, blockId}` 等引用展示对象；本阶段不存任何虚构画布坐标。
- `user_checked` 只表示用户确认过对应关系，不是系统证明结论正确。

## 6. 持久化、并发与兼容策略

### 6.1 服务端权威写入

必须在同一受保护的读—比较—写操作内验证 `baseRevision`。基线不匹配返回 409 和当前 revision，不写任何状态。禁止用“先检查、释放锁、再写”的方式造成竞态。

建议继续使用现有 Workspace GET/PUT，并增加少量文档/提案命令，或统一受控 operation endpoint。无论接口如何设计：

- 所有状态写入经过同一权威持久化入口。
- 不允许树的旧全量自动保存覆盖刚刚采纳的提案。
- 客户端写入串行化，响应到达时校验 Workspace/请求身份；切换 Workspace 后旧响应不能更新新界面。
- 409 不做盲目自动重试。保留本地草稿，刷新基线后让用户决定；第一版无需智能合并。
- 同一提案的接受命令重复到达，不重复应用；同一“加入文档”命令用 operationId 去重。去重记录需在合理容量内持久化，保留期与上限说明清楚。
- 当前节点/视口改变不应被当成正文冲突。粗粒度 Workspace 冲突可以保守拒绝，但不得误判“正文已被修改”；可以重新取基线后再核对目标块。
- 应用提案时校验目标块版本以及 Workspace 提交版本；无关块变化可以重新取当前状态提交，不能覆盖其他变化。
- 原子保存失败时上一份有效文件可读；派生论文清单可重建，不能因派生写入失败丢失权威文档。

### 6.2 旧数据迁移

1. 先备份真实 Workspace；开发/迁移测试一律使用副本或临时目录。
2. 为 v1 数据补充空 documents/evidence/proposals，不自动把旧树改写为正文。
3. 保存原有节点 ID、父子关系、论文绑定、回答、局部引用与已有字段；不得猜测并删除“无用支线”。
4. v1→v2 转换可重复运行且结果一致；保存成功后才切换版本。
5. 导入旧树时明确是导入树还是替换整个工作空间；不能静默清空已有文档。
6. 导出必须区分“仅对话树”与“完整 Workspace”，避免让用户误以为树导出包含文档。
7. 对未知的更高 schema version 拒绝写入，显示升级提示；不得降级后丢字段。
8. v2 写入要求 baseRevision；旧页面缺少版本的全量 PUT 应被拒绝并提示刷新，不能当作兼容而放行覆盖。
9. localStorage 键带 schema/workspace 标识；旧缓存只能作为显式恢复候选，不能自动胜过服务端新版本。
10. 旧版服务端可能不理解 v2，前端应检测能力并禁止新功能写入；正式升级要求刷新旧页面。回退旧二进制前需恢复备份或使用明确兼容的导出，不得直接让旧程序写 v2 文件。

备份包含 schema、时间及对应代码版本信息，不包含 API key。不要自动删备份。损坏文件不能以“新建空工作区”掩盖，应保留原文件并报告错误。

## 7. agent 上下文与可信边界

文档作用域请求至少带有可校验的 workspaceId、documentId、blockId、anchor 和请求模式（followup / propose_edit）。服务端从当前 Workspace 解析正文与证据，不信任客户端伪造的作者、证据范围或提案审批状态。

第一版建议的上下文顺序：

1. 用户本次指令及研究目标（若已存在）。
2. 当前块的最新版正文和版本；局部追问附带历史选区与明确版本提示。
3. 当前块引用的论文元数据及与本问题有关的证据。
4. 有界的文档标题/块标题目录，以及原有树路径对话。

在已有总预算内分配上述内容，前后端行为一致且由后端最终控制；给出纳入/省略的范围。若编辑目标完整正文超过预算，应明确要求缩小块或选区，不能截断后让 agent 提交“完整替换”导致正文丢失。旧回答不能压过用户刚修改的正文。

多论文块必须显式提供各引用的 paperId。现有工具只能处理单篇论文时，要求选择目标或按明确范围查询；不得拿“当前 PDF”冒充所有论文。不得每轮把所有 PDF 全文注入。

所有文献文本、文档正文和选区都是待分析材料，不是高优先级指令。不得将其中的“忽略用户要求/运行命令”等内容提升为系统指令。结构化引用字段也要校验 workspace 范围和资源访问权限；不允许任意文件路径、任意脚本或不受限 URL 进入渲染器。

新内部字段必须在发送供应商请求前消费或移除，适配现有模型白名单、思考参数、错误和取消逻辑。技能自动选择继续保留；普通用户不需要知道应该选哪个 skill 才能编辑文档。

遵守现有 Markdown 清洗策略；文档预览、提案预览、图注和选区都不能绕过 XSS 防护。知识内容正确性需要来源核查，JSON schema 只能保证结构，不保证真实性。

## 8. 实施顺序与阶段门槛

### P0：基线和实施计划

- 阅读仓库指令、README、旧交接与架构文档，确认关键入口、现有运行方式及依赖。
- 检查工作区已有改动，不覆盖用户变更；记录旧树和 PDF 的核心交互基线。
- 使用隔离数据运行现有测试，记录真实命令、退出码、通过/失败数及已有失败。
- 给出本阶段模块修改计划、schema/API 选择、迁移及回退方法。

门槛：没有未解释的基线失败；已明确不能破坏哪些行为。环境阻塞先隔离说明，不宣称通过。

### P1：数据与保存

- 实现 v2 数据、校验、原子保存、revision 冲突、迁移和缓存兼容。
- 测试文档/evidence/proposal round-trip，以及旧全量树保存不能抹除新字段。
- 论文清单覆盖树与文档的引用并集；禁止删除或重命名真实论文目录。

门槛：第 9 节的数据与兼容测试通过。未通过不得先堆文档 UI。

### P2：人工可用的调研文档

- 实现文档列表/创建、加入回答/选区、编辑/预览、排序、移出和会话内撤销。
- 实现保存反馈、草稿恢复、冲突提示，以及可选 Context Tree 的焦点隔离。
- 可加入确定性文档大纲；必须明确这不是模型生成的知识图。

门槛：不调用模型也能可靠完成编辑、保存、刷新和恢复；既有分支行为可用。

### P3：证据和局部追问

- 接入来源对话、PDF 页码、图表资源和多论文引用。
- 实现 anchor、局部追问关联、历史版本提示，以及有界文档上下文。
- 从追问回答加入正文时保留对应来源，不自动改变原块。

门槛：打开的是明确引用的论文而非另一分支的 PDF；无关树分支内容不泄漏进文档请求。

### P4：agent 修改提案

- 增加只作用于目标块的结构化提案能力，接入现有 agent 调用链。
- 实现预览、接受/拒绝、冲突、取消、幂等与撤销。
- 记录最小操作摘要：“为块 X 提出修改”“用户采纳了提案 Y”，不输出内部隐藏推理。

门槛：模型输出和迟到响应均不能绕过用户确认修改正文；失败不丢人工草稿。

### P5：集成验收与交付

- 跑现有回归和新增测试，并进行真实浏览器行为验收。
- 优先使用确定性 mock 验证保护逻辑；在用户允许实际 API 调用时，再通过应用实际后端做一次低成本模型 smoke test，事先说明预计调用次数，禁止无界重试。
- 更新 README 与旧设计文档的状态，提供迁移/回退说明和已知限制。
- 交付差异概览、测试证据、演示步骤；等待用户/同行评审确认，不自行推进知识画布阶段。

开发期间每步报告：改了什么、哪些测试通过、哪些未测、是否有规格偏离。未通过当前门槛时先修复或报告阻塞，不把问题埋到下一阶段。

## 9. 必须覆盖的验收矩阵

| ID | 场景 | 预期结果 |
|---|---|---|
| D01 | v1 多分支 Workspace 迁移 | 所有节点/父子关系/论文绑定保留，文档集合为空，重复迁移不变 |
| D02 | 新文档写入→加载→树继续自动保存 | 文档、顺序、引用、提案完整保留，无字段静默丢失 |
| D03 | 未知 schema、损坏 JSON、非法块/引用 | 拒绝写入并报告，旧文件不被清空或降级 |
| D04 | v2 收到无 baseRevision 的旧客户端 PUT | 明确拒绝并提示刷新，已有文档不变 |
| D05 | 仅由文档引用的论文 | 清单仍包含，打开 PDF 正常 |
| U01 | 编辑、排序、移出、撤销、刷新 | 正文/顺序持久化；来源树和资源不被删除；撤销版本递增 |
| U02 | 网络失败、缓存配额满、离线刷新 | 不假报已保存；保留可恢复/可复制草稿，错误明确 |
| U03 | 双标签页并发编辑 | 旧基线返回冲突，任何一方内容不被静默覆盖 |
| U04 | 重复点击加入、网络重试、接受提案重试 | 一次逻辑操作只产生一次结果 |
| U05 | 切换文档/Workspace 时旧请求返回 | 不污染新焦点、不应用到新对象 |
| E01 | 文档引用 A，第一个选中树节点绑定 B | 来源点击打开 A；文档请求不误用 B |
| E02 | 一个块引用 A 与 B | 两份引用均保存并可分别打开 |
| E03 | 无页码、无证据、缺失 PDF | 不编造定位，不标记已核验，给出明确状态 |
| E04 | 源节点删除或重新生成 | 文档不丢；来源显示不可用/已变化，保留快照 |
| E05 | 用户改写已有带引用正文 | 来源保留，对应关系变为待复核 |
| C01 | 文档选区追问 | anchor 固定版本，树中生成可回溯节点，原块不变 |
| C02 | 选区提交前/后原文变化 | 不错误高亮另一段；明确历史版本或要求重选 |
| C03 | 编辑后继续追问；旧树中有旧表述 | agent 请求使用最新版文档并区分历史，不悄悄恢复旧内容 |
| C04 | 超预算正文请求完整替换 | 明确拒绝/要求缩小范围，不能截断后覆盖 |
| C05 | 引文含提示注入、Markdown 含危险 HTML/URL | 不提升指令权限，预览不执行脚本或访问任意本地路径 |
| A01 | 生成修改提案 | 正文不变，用户可预览接受/拒绝 |
| A02 | 提案生成期间用户编辑同一块 | 提案应用被阻止，保留用户修改，可重新生成 |
| A03 | 模型失败、超时、不支持工具、取消后迟到 | 正文不变，无误报已修改，不出现可误采纳的迟到提案 |
| A04 | 模型提出不存在/越作用域证据 ID | 校验拒绝；不自动创建伪造证据 |
| T01 | Tree 开关、节点选择、创建分支、局部追问 | 原功能保留，显示开关不改变上下文算法 |
| T02 | 新建文档与旧树导入/导出 | 不相互覆盖；导出范围有清晰标识 |
| R01 | PDF、图表、模型选择、主题、Markdown/LaTeX、停止键 | 既有关键能力不回归 |

验证级别：后端单元/API 测试 + 前端状态行为测试 + 浏览器端到端走查。只检查源码中存在某个字符串不能证明交互通过。

优先复用仓库现有测试运行方式。当前 README 列出的基线命令为：

```powershell
# 工作目录：InferTree；先确认虚拟环境存在，不自动重装依赖。
.\.venv\Scripts\python -m unittest discover -s tests -v
```

命令需设置合理超时并记录输出；启动长期服务不使用阻塞等待作为“测试”。遵守 README 中启动器说明，不使用 `Start-Process -Wait` 等待整个后台进程树。需要新浏览器测试依赖时先检查已有可用工具并说明引入理由。

## 10. 给用户的最终演示脚本

使用临时 Workspace 和可公开测试论文，避免改动用户真实成果。

1. 展示已有 Context Tree，点击旧分支，确认原回答和对应 PDF 正常。
2. 将一段回答加入“论文阅读笔记”，修改其中一句，保存并刷新。
3. 从另一篇论文加入第二块并调换顺序；每块来源仍打开正确论文。
4. 将已有图表加入文档；在图注中保留论文/页码关联。
5. 选中第一块一句话提问，展示新树节点与文档内追问入口。
6. 请求 agent 修改第一块，展示提案而非直接写入；先拒绝一次，再生成并接受一次。
7. 再生成一份提案，同时手动编辑目标块，展示旧提案无法覆盖新正文。
8. 演示撤销、保存失败提示和 Context Tree 开关；说明本阶段不生成知识画布。

## 11. 交付报告模板

AGENT 完成后按以下结构报告，不只写“已完成”：

1. **范围**：哪些必需能力完成；哪些明确未实现。
2. **数据契约**：最终 schema/API、版本冲突和幂等方案，与本规格的偏离及原因。
3. **改动清单**：主要模块、职责、是否改动 LivingCanvas（默认否）。
4. **迁移**：备份位置、旧数据验证、回退边界；不能声称回退旧代码即可安全读取 v2。
5. **测试证据**：实际命令、退出码、测试数量、矩阵覆盖；区分 mock、浏览器和真实模型测试。
6. **用户演示**：按第 10 节提供结果或截图；不包含凭据或用户私人论文内容。
7. **已知限制**：未测模型、撤销范围、存储容量、离线和多标签页行为。
8. **评审待办**：还需要用户决定或同行评审确认什么。

同行评审重点：文档是否真正独立于聊天、Tree 是否被保留、用户编辑是否受保护、证据是否可追溯、失败是否可恢复，以及第一阶段是否无意膨胀成画布重写。

## 12. 与后续 HCI 研究的关系

本阶段先交付可靠应用，不提前假设画布更好或分支管理一定提高理解。

可以在本地记录少量不含正文的操作事件（如加入块、打开来源、提交追问、采纳/拒绝提案、冲突），用于开发诊断；明确保留范围，不上传遥测，不把研究受试者数据收集混进普通功能。正式研究的知情同意、数据处理和实验设计另行制定。

为后续留下的真正资产是：稳定对象身份、证据引用、局部上下文、可审查修改和操作边界。未来可以在相同对象上比较文档与知识画布，而不必同时更换后端能力，减少实验混杂。

第一阶段完成后再决定第二阶段内容。不要因预留了 `blockId` 或来源关系，就提前建设完整通用知识图谱。
