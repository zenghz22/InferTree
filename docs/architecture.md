# InferTree 架构蓝图：从「上下文树」到「主线文档 + 支线批注 + 投影地图」

> 状态：方向已定，逐步迁移中。本文是开发的自洽依据，代码以本文为准。
> 相关讨论结论：线性工作流足以覆盖多数场景；树是副产品而非产品；地图按需调出，不占主要注意力。

## 1. 核心定位转变

- **旧定位**：一棵「推理树」，树是产品本身。
- **新定位**：一份「会自己生长的调研文档」。树/地图只是它的**投影**，不占据用户主要注意力。

一句话原则：

> **主线是唯一事实源；其余（地图、大纲、上下文、树）都是它的只读投影。**

## 2. 三条事实（为什么线性够用）

1. 文献调研有固定阶段顺序：`search → download → summary → review → figures`。
2. 用户的分支几乎都是「针对局部追问」，不该与主线平级。
3. 常态下用户只关心主线文档；结构视图按需调出。

## 3. 五条原则

1. **主线是唯一事实源**；大纲/地图/上下文/树都是投影。
2. **主线线性推进**（阶段块），**支线局部附着**，支线永不与主线平级。
3. **地图只读、按需、可跳转**，不可直接编辑。
4. **记忆沿主线压缩**：模型上下文 = 「主线压缩摘要 + 当前焦点块」；支线便宜，因它是局部的。
5. **选项服务于推进主线**（「下一步做什么」）；局部追问走「选中文字」，不再靠选项分叉。

## 4. 数据模型

### 4.1 主线（Spine）
主线是「当前路径」上的一段段**阶段块**（block），每个块对应一次模型回合。

```
root ─→ search ─→ download ─→ summary ─→ review ─→ figures
```

块字段（沿用现有 `node`，新增 `kind` 区分主线/支线）：
- `kind: 'spine' | 'fork'`
- 现有字段沿用：`id / parentId / query / content / reasoning / title / skill / skillMode / paperId / artifacts / ui / …`
- 主线块特有：`paperId`（绑定论文）、`stage`（阶段）、`ui`（下一步选项 = 阶段选择器）。

### 4.2 支线（Fork / 批注）
支线是对主线某块（或其某段文字）的**局部追问**，默认折叠，点开内联查看。

- 由「选中文字 → 追问」产生（现有 `localExcerpt` / `localSourceNodeId` 已承载）。
- 不继承「下一步选项」、不推进主线、不与主线平级。
- 视觉：主线块正常展示；支线显示为块下方折叠 chip「+N 追问」。

### 4.3 地图 / 大纲（Projection）
由主线 + 支线**生成**的只读导航，从不被直接编辑：

- **第一阶段**：大纲 = 主线块的可折叠目录（点击跳转）。
- **第二阶段（可选）**：2D 思维导图 = 同一数据的另一张投影（现有 `renderTree` 树画布演进）。

## 5. 记忆模型（上下文）

- **主线上下文** = 「主线压缩摘要（已完成阶段 + 关键结论）+ 当前焦点块全文 + 论文元数据」。
- **支线上下文** = 「源块内容 + 选中片段 + 主线摘要」——便宜、有界。
- **压缩策略**：沿主线滚动摘要，保留决策与结论，丢弃中间 tool 轮次。

## 6. UI 计划

1. ✅ 重心反转（进行中）：对话区成为主工作台；结构地图默认隐藏，一个按钮调出。
2. 主线块样式：突出阶段徽标（search/download/summary/review/figures）。
3. 支线折叠化：fork 内联折叠为 chip，不与主线平级。
4. 大纲投影：主线块可折叠目录侧栏（作为默认导航）。
