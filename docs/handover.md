# InferTree 转向说明与交接文档

> 更新：最近一轮讨论结束时。本文面向任何接手 InferTree 的开发者（或未来的协作实例），
> 解释「为什么转向」「讨论得出了什么」「接下来做什么」。
> 配合 `docs/architecture.md`（原则与数据模型）一起阅读。

---

## 1. 文档目的

三件事：
1. **转向的原因** —— 我们为什么从「上下文树」转向「主线文档 + 支线批注 + 投影地图」。
2. **几轮讨论的核心内容** —— 每轮的问题与最终结论，避免后人重复踩坑。
3. **后续计划** —— 迁移路径、每步验收、风险与开放问题。

---

## 2. 转向的原因

### 2.1 原始假设
InferTree 立项时的隐喻是「推理树」：每次提问是一个节点，追问产生子树，用户通过树的形状看到推理的分支结构。产品名（InferTree）也因此而来。

### 2.2 实践中的反证（用户亲历观察）
1. **线性工作流已够用**：文献调研有固定顺序 `search → download → summary → review → figures`，多数场景不需要分支。
2. **fork 往往是局部追问**：用户通常是「选中一段文字」追问，本质是对主线某句/某结论的注释，不该与主线平级。
3. **树占据注意力却无助**：常驻的树画布抢占了主要注意力，但对「改进文献调研体验」没有直接帮助。

### 2.3 本质判断

> **树是调研过程的副产品，不是产品本身。** 用户要的是「把一篇论文搞懂」，而不是「看到一棵树」。

因此产品重新定义为：**一份会自己生长的调研文档**。树/地图只是它的**只读投影**，可调出、不占主位。

## 3. 几轮讨论的核心内容（按时间顺序）

### 3.1 第 1 轮：模型如何「给选项」（原理）
**问题**：模型（像我这样的）是怎么做到实时定制交互、给用户选项的？

**结论**：
- 模型**从不写 UI**，只输出**受 schema 约束的类型化 JSON**（function calling）；运行时拦截并**确定性渲染**。
- 三支柱：
  1. **schema 约束** → 让它「会」（输出形状可靠可解析，有些 API 做 constrained decoding）。
  2. **上下文条件** → 让它「定制」（本质是下一 token 预测 + 长上下文，不是模型主动思考）。
  3. **确定性渲染** → 让它「安全」（前端注册表按 `type` 分发，模型注入不了行为）。
- 「实时」靠流式 SSE：工具调用在生成中途被决定就立即推送渲染。
- 主流参考：Vercel AI SDK `streamUI`（生成式 UI，与我们最接近）、Claude Artifacts / OpenAI Canvas（artifact 投影）、Anthropic Computer Use（agentic GUI，另一个极端）、MCP。
- 关键分野：「建议下一步」有两种流派 —— **循环内 in-loop（agentic，模型掌权）** vs **后置 post-hoc（product，产品掌权，如 ChatGPT 底部 chips）**。

### 3.2 第 2 轮：当前工具清单盘点
**结论**：现有 6 个 function-calling 工具，分两类（详见第 5 节工具清单）：
- **闭路工具**（结果回喂模型、同一回合内继续）：`web_search`、`download_paper`、`list_paper_visuals`、`render_paper_visuals`、`activate_skill`。
- **开路工具**（推向用户，循环不暂停）：`ui_action`（options/confirm/input）。用户点击后由前端 `sendAsChild` **新开一个回合/节点**。

### 3.3 第 3 轮：剩余选项由程序保留，还是模型推理？
**问题**：选「摘要」后该选项被消费，但模型没有有效「继承」剩余选项。

**结论**：
- 「剩余菜单」是**确定性状态**，让模型重推必然漏/重复（文字提示无法可靠复现状态）。
- 采用**混合**：程序持菜单（确定性骨架、点击即消费）+ 模型 `ui_action` 增补（上下文专属选项，去重合并）。
- 落地：`WORKFLOW_MENU` 常量 + `menuForNode()` 按路径消费 + `renderUi` 合并去重。

### 3.4 第 4 轮：点击如何回流 —— 树 vs 单线程
**问题**：两者的区别是什么？用户倾向「单线程，点击回喂同一回合续跑」。

**结论（一句话本质）**：
> 回合结束后，模型这一回合的「工作记忆」（工具调用、搜索结果、论文全文、推理）是**丢弃**还是**保留**。

- **树 / 新回合**：丢弃工作记忆，只存最终答案；下一回合从祖先答案重建上下文。
- **单线程 / 同回合**：保留工作记忆；点击 = 追加「用户选了 X」，接着原思路继续。

**关键澄清（2×2 矩阵）**：结构轴（新节点 vs 同节点）× 记忆轴（完整历史 vs 祖先答案）。
用户最初选的「单线程同回合」会把可见的纵向串压成一个节点；为同时保住「可见的串 + 连续记忆」，最终倾向 **B：每次点击开新节点，但新节点承接上一回合的完整工作记忆**（代价：需压缩层控制上下文膨胀）。

### 3.5 第 5 轮：大转向 —— 树 → 文档（定案）
**结论（五条原则，与 `architecture.md` 一致）**：
1. 主线是唯一事实源；大纲/地图/上下文/树都是投影。
2. 主线线性推进（阶段块），支线局部附着，永不与主线平级。
3. 地图只读、按需、可跳转，不可直接编辑。
4. 记忆沿主线压缩：上下文 = 主线压缩摘要 + 当前焦点块；支线便宜（局部）。
5. 选项服务于推进主线；局部追问走「选中文字」。

**一处修正**：用户原说「思维导图」，建议先降级为「大纲（outline）」——主线块的可折叠目录，最实用；2D 思维导图是后加的口味（同一数据的另一张投影）。

## 4. 后续计划

### 4.1 已完成
- **步骤 0**：`ui_action` 三态（options/confirm/input）+ 程序菜单（`WORKFLOW_MENU`）。
- **步骤 1**：UI 重心反转 —— 结构地图默认隐藏、头部「🗺 地图」按钮切换（偏好存 localStorage）、对话区成为全宽主工作台（消息列 920px 居中）。

### 4.2 迁移路径（剩余）

| 步骤 | 目标 | 关键改动 | 验收标准 |
|---|---|---|---|
| **2** | 支线降级 | 引入 `node.kind: 'spine' \| 'fork'`；fork 折叠为 chip「+N 追问」 | 选中文字追问后，主线块下方出现折叠 chip，不与主线平级 |
| **3** | 主线记忆压缩 | 沿主线滚动摘要，丢弃中间 tool 轮次，保留决策/结论/论文元数据 | 深链不爆上下文，模型仍能引用早期结论 |
| **4** | 大纲投影 | 主线块可折叠目录侧栏（点击跳转），作为默认导航 | 一键调出大纲，点击定位到对应块 |
| **5（可选）** | 2D 思维导图 | 同一数据的第二张投影 | 地图只读，从不被直接编辑 |

### 4.3 风险与开放问题
1. **旧树数据迁移**：现有 workspace 的 `nodes` 无 `kind` 字段，需向后兼容（默认按 `parentId`/`localSourceNodeId` 推断 spine/fork）。
2. **记忆压缩的保真度**：丢弃中间 tool 轮次后，如何保证不丢关键证据、页码、作者/标题。
3. **B 方案的上下文膨胀**：每个新节点承接完整工作记忆，必须配合压缩层，否则深链 token 爆炸。
4. **fork 的挂载粒度**：挂到「块」还是「块内具体片段」？现有 `localExcerpt` 支持片段，倾向后者。

## 5. 工具清单（当前 6 个）

| 工具 | 模型 call 什么 | 程序做什么 | 何时可用 |
|---|---|---|---|
| `web_search` | `{query}` | 调 Tavily，结果回喂 | 配了 Tavily key |
| `download_paper` | `{source}` | 下载+解析 PDF，发 `agent_paper` 绑定节点 | 下载器；或审稿/图表且无论文 |
| `list_paper_visuals` | `{}` | 扫图表候选+评分，结果回喂 | 审稿/图表且有论文 |
| `render_paper_visuals` | `{visual_ids ≤4}` | 截图，发 `agent_artifact` 插入对话 | 同上 |
| `activate_skill` | `{skill, reason?}` | 装载技能，注入 system prompt，重排工具表 | 仅 `auto` |
| `ui_action` | `{type, …}` | 规范化成 UI 意图，发 `agent_ui` 渲染 | 只要设了 skill |

> `ui_action` 是唯一「开路」工具：推向用户后循环不暂停，点击由前端 `sendAsChild` 新开回合。

## 6. 关键术语表

- **主线 Spine**：线性推进的阶段块序列（`search → download → summary → review → figures`），即产品本体。
- **支线 Fork / 批注**：对主线某块或某片段的局部追问，默认折叠，不与主线平级。
- **投影 Projection**：由主线+支线生成、只读、可跳转的视图（大纲 / 2D 地图）。
- **阶段块 Block**：主线上的一个回合，对应一个 `node`。
- **阶段选择器**：主线当前块上的「下一步选项」——选项服务的正确身份。
- **工作记忆**：回合内模型调用过的工具、拿到的结果、论文全文、推理；回合结束时是否保留，是树 vs 单线程的分界。
- **闭路工具 / 开路工具**：结果是否回喂模型并同回合继续（闭路）vs 推向用户并等待外部点击（开路）。
- **生成式 UI**：模型选择「渲染哪个组件 + 传什么 props」，props 即类型化数据。
- **in-loop vs post-hoc**：「建议下一步」由主循环内模型决定，还是由产品在答案后另发轻量调用决定。
