## 2. 交互说明（用户视角）

1. 顶栏点 **📄 文档** 打开右侧文档面板（与对话并排）。
2. 点 **＋ 新建** 建文档；点文档标签切换；标题框可直接改名（回车/失焦保存）。
3. 点 **＋ 段落** 新增块；块内直接编辑标题与 Markdown，停止输入约 0.9s 自动保存。
4. 块工具：**↑ ↓** 排序、**✕** 移出、**预览/编辑** 切换渲染。
5. 选中某条回答正文 → **＋ 加入文档** 以「摘录」入档；未选中则整条回答入档。
6. 右上角状态显示 `保存中… / 已保存 · rev N / 未保存… / 保存失败：…`。
7. 异常关闭或刷新后，若草稿未落盘，块底部出现 **⚑ 恢复未保存草稿**。
8. **↩ 撤销** 回退最近一次文档操作（改文本/新增/移出/排序）。

## 3. 数据与协议

- 文档编辑一律走 **`POST /api/workspaces/{id}/operations`**，不直接改写 `workspace.json`。
- 每次操作携带 `operationId`（页面内自增+随机）与 `baseRevision`。
- `block.update` 额外携带 `baseBlockRevision + baseContentHash`（由最近一次服务端状态提供），块级基线不一致 → 409。
- **409 处理**：`workspaceRevision` 过期时，先 `GET` 同步版本，再以**同一 `operationId`** 重试一次。同一 ID 保证幂等——若首次实际已提交，重试返回 `duplicate: true`，不会重复执行；因此重试不会产生重复块。
- **树保存 409**：`reconcileTreeConflict()` 比对服务端树与 `lastCommittedTree`；一致→安全重试（本页操作推进了版本）；不一致→提示「其他页面已修改会话树」并**停止自动保存**，不覆盖他页修改。
- **草稿键**：`inferTree:draft:v1:<workspace>:<docId>:<blockId>`；保存成功后清除。
- **树存储键**：`inferTree:tree:v2:<workspace>`；读取时若缺失则从旧键 `tree` 一次性迁移。

## 6. 如何测试（重要：顺序）

文档面板依赖 P1 的 operations 端点，因此需要**新后端**：

1. 先 **Ctrl+F5** 刷新页面，拿到新前端（新前端本身兼容旧后端，刷新不会坏）。
2. 再**重启后端服务**（关闭当前 InferTree 进程后重新启动）。
3. 再次刷新页面，点 **📄 文档** 验证第 2 节流程。

反向顺序也可用，但旧前端对新后端保存会短暂报 422（前端会保留本地副本并在下次成功保存时自愈）。

## 7. 已知限制

- 新建文档用浏览器 `prompt()` 取标题（轻量首版），后续可改内联输入。
- 撤销以「反向 operation」实现，不复用服务端事务；撤销「移出」会以新 blockId 重建内容（内容与来源保留）。
- 文档面板与 PDF 面板同时打开时空间偏紧（两者都占用右侧宽度）。
- 图表块已支持渲染与「资源缺失明确报错」，但入口与视觉素材绑定留待 P3。
- 自动保存为 900ms 防抖，极端情况下（输入后立即关页）依赖草稿恢复。
